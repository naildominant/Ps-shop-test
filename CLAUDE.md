# PS SHOP: памятка для Claude

Полное ТЗ: `docs/TZ.md`. Читай его перед любой работой над сайтом и обновляй, когда пользователь принимает новые решения.

## Пользователь
- Владелец магазина PS SHOP, не программист. Общаемся по-русски, простыми словами, без жаргона.
- Объясняй по шагам, особенно всё, что нужно нажать на GitHub или в Telegram. Пользователь часто сидит с телефона.
- Инструкции давай по 1–2 действия за сообщение, жди ответа и только потом следующий шаг.
- Задачи из списка делай строго по одной: закончил одну, показал результат и ждёшь подтверждения владельца, только потом следующая.
- Вопросы задавай обычным текстом, по одному. **Не используй кнопки-варианты (AskUserQuestion)**: владельцу неудобно, он отвечает сам.

## Принятые решения
- Статический сайт без сервера: GitHub Pages и позже свой домен.
- Каталог обновляется автоматически из Telegram-канала (GitHub Actions по расписанию). Посты по шаблону из `docs/TZ.md`.
- Чат = автопомощник (цены и частые вопросы) с переходом к менеджеру в Telegram.
- Корзина в localStorage, заказ отправляется текстом в Telegram менеджеру.
- Без логотипов и фирменного стиля Sony: свой стиль PS SHOP.
- CRM: Google Таблица «PS SHOP CRM» (id 17MKwvBfqCoRMtiqSskPOet4wRO1ewuvyEGjeSPIFCZc, доступна через Google-коннектор). Листы: «Мой отчёт» (простым языком), «Заявки», «Посетители» (анонимный журнал визита), «Сводка». Скрипт в Google универсальный (docs/google-sheet-script.js): новые колонки добавляются только в worker/worker.js (visitRow), скрипт не менять.

## Как работать
- **Память между чатами — `docs/state/`** (`sayt.md` — чаты «САЙТ PS SHOP #N», `bot.md` — «БОТ ПОСТИК #N»). Это твоя память: в начале работы прочитай свою базу знаний полностью. Когда принято важное решение, что-то настроено или закончен этап — сразу допиши в базу и сохрани в `main` (владелец разрешил пушить эти служебные файлы в main без «публикуй»). Ничего не удалять без замены, устаревшее — в «Архив». Журналы `*-log.md` читать по необходимости.
- **Ежедневный перенос чатов:** задача «Ежедневный перенос сессий PS SHOP» (id trig_01RiGzknLmLGVeHfVzjTLZRT) каждый день в 5:31 по Ташкенту создаёт новый чат «<ИМЯ> #N+1» (если в старом была активность за сутки), передаёт ему итог суток, и новый чат дописывает его в `docs/state/`. Главное для владельца — экономия лимитов.
- **Экономия контекста (скиллы `token-efficiency`, `token-optimization`, `strategic-compact`):** сначала ответ, без вступлений и пересказа; искать перед чтением, читать диапазоны строк; независимые вызовы — одним блоком; не перечитывать файл после успешной правки; длинный вывод — через фильтр. Важные решения и состояние записывать в файлы (CLAUDE.md, `designer/journal.md`, `designer/STATE.md`), а не держать только в разговоре. Сжимать разговор на границах этапов (после публикации поста, перед новой задачей), не посреди работы.
- Дизайн: используй скилл `frontend-design` (`.claude/skills/`). После вёрстки прогоняй экраны через скилл `unslop`, чтобы убрать признаки «сделано нейросетью».
- Картинки (баннеры, постеры, обложки для постов и сайта в PNG/PDF): скилл `canvas-design` (`.claude/skills/canvas-design`, шрифты в `canvas-fonts/`).
- Воркер Cloudflare `psshop` меняют несколько сессий (сайт и «БОТ ПОСТИК»). Перед каждым деплоем скачивать живую версию (`GET .../workers/scripts/psshop/content/v2`), вносить правки в неё и только потом выкладывать.
- Проверка: скилл `webapp-testing`. Перед сдачей проверяй главную, каталог, страницу игры, корзину и чат на ширине телефона (~390px) и компьютера.
- Главное — телефон: быстрая загрузка, сжатые обложки (webp), ленивая загрузка картинок.
- Наработки теста: `tools/` (парсер канала), `games.js` (каталог), `covers/` (обложки).
