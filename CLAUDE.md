# PS SHOP: памятка для Claude

Полное ТЗ: `docs/TZ.md`. Читай его перед любой работой над сайтом и обновляй, когда пользователь принимает новые решения.

## Пользователь
- Владелец магазина PS SHOP, не программист. Общаемся по-русски, простыми словами, без жаргона.
- Объясняй по шагам, особенно всё, что нужно нажать на GitHub или в Telegram. Пользователь часто сидит с телефона.
- Инструкции давай по 1–2 действия за сообщение, жди ответа и только потом следующий шаг.
- Задачи из списка делай строго по одной: закончил одну, показал результат и ждёшь подтверждения владельца, только потом следующая.
- Вопросы задавай обычным текстом, по одному. **Не используй кнопки-варианты (AskUserQuestion)**: владельцу неудобно, он отвечает сам.

## Команда (решение владельца 22.11)
- **Бос** — чат «Бос #N», руководитель: владелец даёт задачи через него, Бос раздаёт и следит. **Сайтер** — «Сайтер #N» (сайт). **Постик** — «Постик #N» (бот постов). **Мастер** — «Мастер #N» (настройка Claude, правила, перенос чатов).

## Как работать
- **Память между чатами — `docs/state/`** (`sayt.md` — чаты «Сайтер #N», `bot.md` — «Постик #N», `claude.md` — «Мастер #N», `bos.md` — «Бос #N»). Это твоя память: в начале работы прочитай свою базу знаний полностью. Когда принято важное решение, что-то настроено или закончен этап — сразу допиши в базу и сохрани в `main` (владелец разрешил пушить эти служебные файлы в main без «публикуй»). Ничего не удалять без замены, устаревшее — в «Архив». Журналы `*-log.md` читать по необходимости.
- **Ежедневный перенос чата (правило, принято владельцем 22.11):** касается рабочих чатов с названием «<Имя> #N»: «Сайтер» → память `docs/state/sayt.md`, «Постик» → `bot.md`, «Мастер» → `claude.md`, «Бос» → `bos.md` (до 22.11 назывались «САЙТ PS SHOP», «БОТ ПОСТИК», «НАСТРОЙКА CLAUDE», «БОС»). Получив сообщение владельца, если ты ещё не проверял сегодня: узнай дату создания своего чата (get_session без id, created_at) и сегодняшнюю дату по Ташкенту (`TZ=Asia/Tashkent date +%F`). Если чат создан раньше сегодняшнего дня — сначала перенесись, потом отвечай:
  1. Допиши в свою базу знаний всё важное из этого чата (новое добавить, изменившееся исправить, ничего не удалять без замены, устаревшее — в «Архив»), в `*-log.md` — запись «## <дата> — <название чата>»; закоммить только эти файлы и запушь в main (git fetch, поверх origin/main, `git push origin HEAD:main` — владелец разрешил).
  2. create_session: title «<Имя> #N+1», source_url https://github.com/naildominant/Ps-shop-test, model — твоя, prompt: «Продолжение чата «<название>». Прочитай CLAUDE.md и docs/state/<файл> — это твоя память. На чём остановились: <2–5 строк>. Первое сообщение владельца за сегодня: «<его сообщение дословно>». Ответь на него как обычно.»
  3. set_session_tags: новому чату добавь «ui:pinned», со своего сними. Старый не архивировать.
  4. Владельцу ответь одной строкой: «Перешёл в новый чат «<Имя> #N+1» (закреплён наверху), ответ там.» Больше в старом чате ничего не делай.
  Если перенос не удался — скажи владельцу коротко и ответь на его сообщение здесь. Запуски по расписанию для переноса не годятся (нет инструментов сессий; задачи trig_013eQidhNZQAXPemVctzKAFE и trig_01FG8Wqc5fTb7i7mVp94iWKw выключены).
- **Экономия контекста (скиллы `token-efficiency`, `token-optimization`, `strategic-compact`):** сначала ответ, без вступлений и пересказа; искать перед чтением, читать диапазоны строк; независимые вызовы — одним блоком; не перечитывать файл после успешной правки; длинный вывод — через фильтр. Важные решения и состояние записывать в файлы (CLAUDE.md, `designer/journal.md`, `designer/STATE.md`), а не держать только в разговоре. Сжимать разговор на границах этапов (после публикации поста, перед новой задачей), не посреди работы.
- Дизайн: используй скилл `frontend-design` (`.claude/skills/`). После вёрстки прогоняй экраны через скилл `unslop`, чтобы убрать признаки «сделано нейросетью».
- Картинки (баннеры, постеры, обложки для постов и сайта в PNG/PDF): скилл `canvas-design` (`.claude/skills/canvas-design`, шрифты в `canvas-fonts/`).
- Воркер Cloudflare `psshop` меняют несколько сессий (сайт и «БОТ ПОСТИК»). Перед каждым деплоем скачивать живую версию (`GET .../workers/scripts/psshop/content/v2`), вносить правки в неё и только потом выкладывать.
- Проверка: скилл `webapp-testing`. Перед сдачей проверяй главную, каталог, страницу игры, корзину и чат на ширине телефона (~390px) и компьютера.
- Главное — телефон: быстрая загрузка, сжатые обложки (webp), ленивая загрузка картинок.
- Наработки теста: `tools/` (парсер канала), `games.js` (каталог), `covers/` (обложки).
