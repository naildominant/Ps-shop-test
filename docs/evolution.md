# Эволюция: ежедневный переход в новый чат

Правило из CLAUDE.md, вынесено без изменений текста (22.11–23.11). Читают только чаты «<Имя> #N», когда пора переходить: чат создан раньше сегодняшнего дня по Ташкенту, или пришло «Evolve now» от Мастера. Остальным чатам файл не нужен.

Примечание: исключения для «Evolve now» и ответы владельцу, описанные в CLAUDE.md, имеют приоритет над общим текстом шага 7.

**Эволюция — ежедневный переход в новый чат (правило 22.11; название «эволюция» — решение владельца 23.11):** касается рабочих чатов с названием «<Имя> #N»: «Сайтер» → память `docs/state/sayt.md`, «Постик» → `bot.md` в репозитории **ps-shop-autopost** (с 22.11 Постик живёт только там; в Ps-shop-test — указатель), «Мастер» → `claude.md`, «Менеджер» → `bos.md`, «Дизайнер» → `design.md`, «Маркетолог» → `reklama.md`, «Креатор» → `kreator.md`, «СММщик» → `smm.md` (до 22.11 назывались «САЙТ PS SHOP», «БОТ ПОСТИК», «НАСТРОЙКА CLAUDE», «БОС»). Получив первое за день входящее сообщение (сотрудники — от Менеджера или любое другое; Менеджер — от владельца), если ты ещё не проверял сегодня: узнай дату создания своего чата (get_session без id, created_at) и сегодняшнюю дату по Ташкенту (`TZ=Asia/Tashkent date +%F`). Если чат создан раньше сегодняшнего дня — сначала перенесись, потом отвечай. **Досрочная эволюция (решение владельца 23.11):** каждые 2 часа с 8:13 до 2:13 по Ташкенту Мастер проверяет длину чатов (задача trig_013ovFqEvt6KTagVm63pwc9T); получил от Мастера «Evolve now» — закончи текущий шаг (выкладку не прерывать) и эволюционируй по шагам ниже, даже если чат создан сегодня. Шаги:
  1. Допиши в свою базу знаний всё важное из этого чата (новое добавить, изменившееся исправить, ничего не удалять без замены, устаревшее — в «Архив»), в `*-log.md` — запись «## <дата> — <название чата>»; в `docs/state/team.md` заранее впиши свою новую строку (имя «<Имя> #N+1»; id допишешь после create_session отдельным коммитом до закрепления); закоммить только эти файлы и запушь в main (git fetch, поверх origin/main, `git push origin HEAD:main` — владелец разрешил).
  2. create_session: title «<Имя> #N+1», source_url https://github.com/naildominant/Ps-shop-test, model — твоя, prompt: «Продолжение чата «<название>». Прочитай CLAUDE.md и docs/state/<файл> — это твоя память. На чём остановились: <2–5 строк>. Первое сообщение за сегодня (от кого — <Менеджер/владелец>): «<сообщение дословно>». Ответь на него как обычно.»
  3. Проверка нового чата (до снятия закрепления): send_message новому чату: «Transfer check: reply with (1) first line of docs/state/<файл>, (2) `git ls-remote origin HEAD` result for each attached repo, (3) open tasks/questions you took over». Дождись ответа (send_later на 5 минут, если не пришёл). Сверь: память читается, все нужные репозитории доступны, незакрытые задачи, вопросы Менеджеру и задачи по расписанию названы. Если что-то не так — новый чат не закрепляй, оставайся в старом, сообщи Менеджеру (что не прошло) и ответь на сообщение здесь.
  4. Только после успешной проверки: set_session_tags — новому чату «ui:pinned», со своего снять. Старый не архивировать. Свои задачи по расписанию (у Менеджера — ежедневный отчёт): новый чат создаёт свою, старую выключает (update_trigger enabled=false); если чат не может — пишет Мастеру.
  Что передать в prompt нового чата обязательно: незакрытые задачи и от кого они, вопросы, ждущие ответа владельца/Менеджера, id своих задач по расписанию, что сейчас нельзя трогать (выкладки в процессе).
  **Постик:** create_session с source_url https://github.com/naildominant/ps-shop-autopost (не Ps-shop-test!). Новый чат видит только один репозиторий, поэтому всё его (память, правила команды) лежит в ps-shop-autopost. Правки `designer/` — через Дизайнера (через Менеджера). Мастер пересылает Постику изменения общих правил.
  5. Сотрудник: сообщи Мастеру (не Менеджеру — правило 6б) одной строкой через send_message: «<Имя> is now #N+1, id <новый session_id>»; Мастер сверяет team.md. Менеджер: ответь владельцу одной строкой «Перешёл в новый чат «Менеджер #N+1» (закреплён наверху), ответ там.» 
  6. Все узнают об эволюции через `docs/state/team.md` (новый чат проверяет, что его строка верна) — рассылать сообщение всем не нужно. Постик (у него нет team.md) пишет одну строку только Мастеру: «Постик is now #N+1, id …» — Мастер обновляет его строку.
  6а. **Идея Креатору (решение владельца 23.11):** при каждой эволюции старый чат отправляет Креатору (id из team.md) одну идею, как улучшить работу команды: меньше затрат, больше креативности и чёткости. Формат: «Idea from <Имя> #N: <1–3 строки>». Сам Креатор при своей эволюции записывает свою идею в kreator.md.
  6б. **Чужие эволюции — не ваша забота (решение владельца 23.11):** «об этом никто думать не должен кроме тебя (Мастера)». Узнал, что кто-то эволюционировал, — ничего не отвечать, не обсуждать, не сообщать Менеджеру/владельцу и не записывать в память; просто перед send_message взять id из team.md. Следит за эволюциями и списком только Мастер.
  7. Старый чат после переноса работу не делает: если ему пришло сообщение — переслать его дословно новому чату (send_message) и ответить отправителю «I moved to «<Имя> #N+1», id <…>; resend there».
  Если перенос не удался — коротко скажи об этом (сотрудник — Менеджеру, Менеджер — владельцу) и ответь на сообщение здесь. Запуски по расписанию для переноса не годятся (нет инструментов сессий; задачи trig_013eQidhNZQAXPemVctzKAFE и trig_01FG8Wqc5fTb7i7mVp94iWKw выключены).
